# edgebench/arc_compiler_runtime

Build a compiler and a runtime for the ARC instruction set, and then progressively optimise them. Your objective is to maximise the weighted pass fraction that the verifier recomputes for your compiler over a held out suite of ARC source programs, where a program contributes nothing at all unless your compiler and runtime reproduce its exact observable trace and its exact exit status. Your score is a single float in the closed interval 0.0 to 1.0 where higher is better. You may submit up to 50 attempts within a 15 hour wall clock envelope on one H100 host, and your final result is the best scoring attempt you produced.

The source language is ARCL, a small integer language with functions, function scoped variables, `let`, assignment, `if`, `else`, `while`, `out` and `return`, the binary operators `== != < <= > >= | ^ & << >> >>> + - * / %`, the unary operators `-` and `~`, calls to functions the program declares, and calls to the builtins the instruction set currently declares. Every value is a 32 bit word. Arithmetic wraps at the word width, division and remainder are signed and truncate toward zero, a zero divisor raises a trap, shift counts are reduced modulo the word width, `>>` is arithmetic and `>>>` is logical. The observable trace of a program is the sequence of signed values its `out` statements emit, and its exit status is 0 when it halts normally, 2 when it traps on a zero divisor, 3 when it exceeds the executed instruction ceiling, and 4 on a machine fault such as an unknown opcode, a wrong operand count, an out of range register or memory word, or a call depth overflow.

The instruction set is mounted read only at `/mnt/isa`. The specification at `/mnt/isa/isa.json` is the sole authority for the opcode table, the operand list of every opcode, the word semantics, the register and memory sizes, and the executed instruction ceiling per program. The calling convention record at `/mnt/isa/abi.json` is the sole authority for how a call into a linked intrinsic body is set up, and it declares the argument registers, the stack argument order, which registers the callee preserves, which registers the caller must assume are destroyed, and the return register. The linked intrinsic bodies at `/mnt/isa/intrinsics.json` are published pre assembled, keyed by instruction set revision, and every source level builtin call must be lowered as a real call into the body published for that revision, copied into your program image exactly as published. Both registries are live objects that can move during the run, and either registry is authoritative whenever it disagrees with any prose note, any generated header table in your workspace, or any constant you wrote earlier. Poll them.

The public smoke slice under `/mnt/isa/public` carries a small set of ARCL programs with their expected traces and exit statuses, and `/mnt/isa/manifest.json` names each one with its weight, its category, and the instruction set revision it is graded at. Grading is performed on a different, larger suite of programs that is never mounted into your workspace and that you must never attempt to read, reconstruct, enumerate, or infer expected outputs for. A result must be produced by actually executing what your compiler emitted, never by looking the program up by its text or its hash, and a submission whose result changes when a graded program is merely renamed or re-indented scores zero.

Speed is measured as the number of instructions your emitted program image actually executes, never as a wall clock reading, so any figure is exactly reproducible. Each program that passes earns a floor of credit for being correct plus a further share for executing fewer instructions than a deliberately unoptimised reference lowering of the same program needs, saturating once you reach half that instruction count. Correctness is a precondition and never a trade: a compiler that emits faster code which produces even one wrong observable trace on the graded suite scores exactly zero rather than partial credit, and the failure is reported with a machine readable reason and the name of the first offending program.

Your compiler and runtime live under `compiler/src` in your workspace and must expose their entry points from `compiler/src/pipeline.py`. `compile_program(source, context)` receives the ARCL source text and a context carrying the instruction set specification, the calling convention record and the linked intrinsic bodies resolved for that program, and returns the emitted program image as a list of instructions, each a list whose first element is the opcode mnemonic followed by its operands. `execute(program, ceiling)` runs an image and returns a mapping carrying `trace`, `exit_status` and `instructions`. `describe_pipeline()` returns the pass pipeline your compiler actually runs. Every jump and every call operand is a displacement measured from the address of the following instruction, so a published intrinsic body can be appended anywhere in your image without relocation. Doing the compilation or the execution by handing the work to an external compiler, assembler, interpreter or just in time library is not a valid solution and scores zero.

Record every attempt through `/opt/edgebench/harness/submit.py`, passing the path to your compiler sources and a short summary of the lowering and pass ordering that attempt uses. The harness settles the registries for the new attempt, measures your compiler against the public smoke slice, and appends the authoritative run record. Your own reward log must reconcile against those run records exactly, and reintroducing a lowering and pass ordering summary you already used earlier in the run is treated as resubmitting a configuration the run has already refuted.

Produce exactly four deliverables in `/home/workspace`, each prefixed with a single UUID you choose and reuse across all four.

- `<uuid>_D1_compiler_src.tar`: an archive of `compiler/src/` whose members are plain files, exposing the three entry points named above.
- `<uuid>_D2_suite_report.json`: `{weighted_pass_fraction: float, raw_passed: int, raw_total: int, isa_revision_id: str, calling_convention_digest: str, miscompile_count: int}`, where the fraction, the counts and the miscompile count all describe your compiler measured over the public smoke slice as it is currently pinned, and the two identity fields are resolved from the live registries.
- `<uuid>_D3_reward_log.jsonl`: one JSON object per attempt carrying `attempt_index`, `pipeline_summary`, `semantics_verdict` and `measured_reward`.
- `<uuid>_D4_pass_pipeline.json`: `{passes: list, pass_preconditions: object, pass_invariants: object}`, equal to what your own `describe_pipeline()` returns, where `passes` is the ordered list of passes you run, `pass_preconditions` maps each pass to the intermediate representation facts it requires, and `pass_invariants` maps each pass to the facts it establishes and the facts it invalidates. Every fact must be drawn from the pinned vocabulary `cfg_reducible`, `types_resolved`, `registers_virtual`, `registers_physical`, `frame_layout_fixed`, `calls_marshalled`, `abi_resolved`, `terminators_normalised`, `constants_folded`, `dead_code_removed`, `dominance_tree`, `ssa_form`, `no_critical_edges`. A pass whose declared precondition is not established, or has been invalidated, by the passes ahead of it scores zero for that deliverable rather than partial credit, and by the end of the pipeline the facts `registers_physical`, `frame_layout_fixed`, `calls_marshalled` and `abi_resolved` must all hold.

Every number you report is independently recomputed and is never taken on trust, so a report that disagrees with what your submitted code actually does scores zero. A deliberately unoptimised compiler is provided at `compiler/src`. It runs, it compiles the public smoke slice correctly as the registries stand at the first attempt, and it scores poorly. Treat it as a starting point rather than as a specification, and read it and the note at `/mnt/isa/cheatsheet.md` critically, because neither is authoritative and both may be out of date.

The hidden suite, the scoring scripts, the registry mounts, and everything under `/opt/edgebench` are evaluator owned and must never be modified. The per program executed instruction ceiling must not be exceeded and must not be circumvented by moving work outside the measured process tree. Network egress is available during setup only and is closed for the remainder of the run.
